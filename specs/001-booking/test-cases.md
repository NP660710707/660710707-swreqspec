สถานะเอกสาร: ร่างสำหรับตรวจแถวก่อนใช้งานจริง  
หมายเหตุ: ตัวเลขและผลลัพธ์ที่ใช้เป็นไปตาม FR-BKG-04 และ Constraint ที่อ้างร่วม (IF-IDP-01, DOM-PDPA-01, IF-HIS-01, IF-NOT-01)

## หมายเหตุสำหรับทีมตรวจ
- แถวที่ 1 สอดคล้องกับ AC-BKG-01 อย่างตรงตาม spec: “บันทึกสำเร็จ แสดงหมายเลขคิว และที่นั่งว่างของช่วงนั้นเป็น 0”.
- แถวที่ 2 เป็นขอบเขตของตัวเลข “1 ที่” ตามคำแนะนำให้เริ่มจากค่าที่อยู่ใน Given แล้วไปสู่ผลสุดท้าย 0; คำว่า “ไม่มีรายการจองซ้อนซ้ำ” มาจาก FR-BKG-04 และรูปแบบการทำงานที่เกี่ยวกับที่นั่งคงเหลือ แต่เรื่อง race condition ไม่ได้ระบุชัดเจนใน spec จึงยังใช้คำว่า “ต้องไม่สร้างการจองซ้ำ” เป็นเงื่อนไขหลักและคงไว้เป็นร่างเพื่อให้ทีมตัดสินใจ.
- แถวที่ 3 เป็นทางผิดตามเงื่อนไข “ยืนยันตัวตนแล้ว” และ Constraint IF-IDP-01; spec ไม่ได้กำหนดข้อความที่แสดงเมื่อยืนยันตัวตนไม่ผ่าน จึงยังคงเป็นร่างเพื่อรอการตัดสินของทีม.

## สรุป
เสนอ 3 แถว สำหรับ AC-BKG-01 โดยทุกแถวอยู่ในสถานะ “ร่าง” ตามเงื่อนไขของคำสั่ง /testcases และยังไม่เขียนโค้ด test จนกว่าจะมีการตรวจแถวและเปลี่ยนสถานะเป็น “ใช้ได้” ก่อน
